# 07 触发器

PG 的触发器分两部分：**触发器函数**（返回 `trigger`）+ `CREATE TRIGGER` 绑定。Oracle 的触发器体直接内联，迁移时要拆成两个对象。

## 1. 行级触发器模板

```sql
-- Oracle
CREATE OR REPLACE TRIGGER trg_order_bi
BEFORE INSERT OR UPDATE ON t_order
FOR EACH ROW
WHEN (NEW.status IS NULL)
BEGIN
  :NEW.status := 'N';
  :NEW.updated_at := SYSDATE;
END;
/
```

```sql
-- PG14
CREATE OR REPLACE FUNCTION trg_order_bi() RETURNS trigger
LANGUAGE plpgsql AS $fn$
BEGIN
  IF NEW.status IS NULL THEN
    NEW.status := 'N';
  END IF;
  NEW.updated_at := LOCALTIMESTAMP(0);
  RETURN NEW;
END;
$fn$;

CREATE TRIGGER trg_order_bi
BEFORE INSERT OR UPDATE ON t_order
FOR EACH ROW
WHEN (NEW.status IS NULL)
EXECUTE FUNCTION trg_order_bi();
```

| Oracle | PG14 |
|---|---|
| `:NEW.col` / `:OLD.col` | `NEW.col` / `OLD.col` |
| `INSERTING` / `UPDATING` / `DELETING` | `TG_OP = 'INSERT'` / `'UPDATE'` / `'DELETE'` |
| `REFERENCING OLD AS o NEW AS n`（行级） | 固定 `NEW`/`OLD`，把 `o.`/`n.` 改成 `OLD.`/`NEW.` |
| `BEFORE` / `AFTER` | 同 |
| `FOR EACH ROW` | 默认行级；语句级写 `FOR EACH STATEMENT` |
| `WHEN (cond)` | `WHEN (cond)`，不能含子查询 |
| `UPDATE OF col` | 支持，但只对 UPDATE 事件有效 |
| `INSTEAD OF`（视图） | 同，仅行级 |
| `FOLLOWS` / `PRECEDES` | 无；同一事件按触发器名字母序执行，用 `01_`、`02_` 前缀控制 |
| `ENABLE` / `DISABLE` | `ALTER TABLE t ENABLE/DISABLE TRIGGER trg` |
| `ALTER TRIGGER ... RENAME` | `ALTER TRIGGER ... RENAME TO` |
| `DROP TRIGGER` | `DROP TRIGGER trg ON t` |

返回规则：
- `BEFORE` 行级：`RETURN NEW` 继续（可修改 `NEW`）；`RETURN NULL` 跳过该行操作；`DELETE` 场景 `RETURN OLD`。
- `AFTER` 行级：返回值被忽略，惯例 `RETURN NULL`。
- 语句级：`RETURN NULL`。
- `INSTEAD OF`：返回 `NEW`（或 `NULL` 表示不操作）。

## 2. 语句级触发器与过渡表

Oracle：

```sql
CREATE OR REPLACE TRIGGER trg_order_audit
AFTER UPDATE ON t_order
DECLARE
BEGIN
  INSERT INTO t_order_audit (id, changed_at)
  SELECT id, SYSDATE FROM t_order WHERE ...;  -- Oracle 里不能直接读 mutating table
END;
```

PG14（过渡表，仅 AFTER、非约束触发器、不能与列清单/INSTEAD OF 同用）：

```sql
CREATE OR REPLACE FUNCTION trg_order_audit() RETURNS trigger
LANGUAGE plpgsql AS $fn$
BEGIN
  INSERT INTO t_order_audit (id, changed_at)
  SELECT n.id, LOCALTIMESTAMP(0) FROM new_rows n;
  RETURN NULL;
END;
$fn$;

CREATE TRIGGER trg_order_audit
AFTER UPDATE ON t_order
REFERENCING NEW TABLE AS new_rows
FOR EACH STATEMENT
EXECUTE FUNCTION trg_order_audit();
```

- 过渡表名 `new_rows` / `old_rows` 在函数里当普通表用。
- 行级触发器里读同一张表：Oracle 报 `ORA-04091`（mutating table），PG 不报但看到的是语句快照，**语义可能不同**；需要审计/汇总时优先用语句级 + 过渡表。
- 分区表上的触发器：行级触发器会传播到分区；过渡表在分区表上不可用（PG14）。

## 3. 常见写法

**自增主键（序列 + 触发器）**

```sql
CREATE OR REPLACE FUNCTION trg_order_bid() RETURNS trigger
LANGUAGE plpgsql AS $fn$
BEGIN
  IF NEW.id IS NULL THEN
    NEW.id := nextval('seq_order_id');
  END IF;
  RETURN NEW;
END;
$fn$;

CREATE TRIGGER trg_order_bid BEFORE INSERT ON t_order
FOR EACH ROW EXECUTE FUNCTION trg_order_bid();
```

（更简单：列上 `GENERATED BY DEFAULT AS IDENTITY` 或 `DEFAULT nextval(...)`，能不用触发器就不用。）

**审计**

```sql
CREATE OR REPLACE FUNCTION trg_order_aiud() RETURNS trigger
LANGUAGE plpgsql AS $fn$
BEGIN
  IF TG_OP = 'DELETE' THEN
    INSERT INTO t_order_audit (id, op, changed_by, changed_at, old_row)
    VALUES (OLD.id, TG_OP, session_user, LOCALTIMESTAMP(0), to_jsonb(OLD));
    RETURN OLD;
  ELSIF TG_OP = 'UPDATE' THEN
    INSERT INTO t_order_audit (id, op, changed_by, changed_at, old_row, new_row)
    VALUES (NEW.id, TG_OP, session_user, LOCALTIMESTAMP(0), to_jsonb(OLD), to_jsonb(NEW));
    RETURN NEW;
  ELSE
    INSERT INTO t_order_audit (id, op, changed_by, changed_at, new_row)
    VALUES (NEW.id, TG_OP, session_user, LOCALTIMESTAMP(0), to_jsonb(NEW));
    RETURN NEW;
  END IF;
END;
$fn$;

CREATE TRIGGER trg_order_aiud AFTER INSERT OR UPDATE OR DELETE ON t_order
FOR EACH ROW EXECUTE FUNCTION trg_order_aiud();
```

`to_jsonb(OLD)` 需要表有主键或至少可转 JSON（大多数类型可以）；大表审计建议只记录变更列。

**校验**

```sql
CREATE OR REPLACE FUNCTION trg_order_check() RETURNS trigger
LANGUAGE plpgsql AS $fn$
BEGIN
  IF NEW.amount < 0 THEN
    RAISE EXCEPTION 'amount must be >= 0 (id=%)', NEW.id USING ERRCODE = 'P0001';
  END IF;
  RETURN NEW;
END;
$fn$;
```

能用 `CHECK` 约束就别用触发器：约束更可靠、可 `NOT VALID` 分批校验。

**更新关联汇总**

Oracle 里常见「子表变更 → 更新主表汇总列」。PG 行级触发器可用，但要注意：
- 触发器里更新主表会加锁，可能死锁；
- 批量操作时逐行触发性能差；
- 更稳的方案是语句级触发器 + 过渡表 + 一条 `UPDATE ... FROM (SELECT ... GROUP BY ...)`。

## 4. 视图上的 INSTEAD OF

```sql
CREATE OR REPLACE FUNCTION trg_v_active_order_iud() RETURNS trigger
LANGUAGE plpgsql AS $fn$
BEGIN
  IF TG_OP = 'INSERT' THEN
    INSERT INTO t_order (id, amount, status) VALUES (NEW.id, NEW.amount, NEW.status);
    RETURN NEW;
  ELSIF TG_OP = 'UPDATE' THEN
    UPDATE t_order SET amount = NEW.amount, status = NEW.status WHERE id = OLD.id;
    RETURN NEW;
  ELSE
    DELETE FROM t_order WHERE id = OLD.id;
    RETURN OLD;
  END IF;
END;
$fn$;

CREATE TRIGGER trg_v_active_order_iud
INSTEAD OF INSERT OR UPDATE OR DELETE ON v_active_order
FOR EACH ROW EXECUTE FUNCTION trg_v_active_order_iud();
```

## 5. DDL 触发器（事件触发器）

Oracle `AFTER CREATE OR DROP ON SCHEMA` / `AFTER ALTER ON DATABASE` → PG `EVENT TRIGGER`：

```sql
CREATE OR REPLACE FUNCTION trg_ddl_audit() RETURNS event_trigger
LANGUAGE plpgsql AS $fn$
BEGIN
  INSERT INTO t_ddl_audit (event, object_type, object_identity, changed_by, changed_at)
  SELECT TG_EVENT, cmd.object_type, cmd.object_identity, session_user, LOCALTIMESTAMP(0)
  FROM pg_event_trigger_ddl_commands() cmd;
END;
$fn$;

CREATE EVENT TRIGGER trg_ddl_audit ON ddl_command_end
EXECUTE FUNCTION trg_ddl_audit();
```

- 事件触发器需要超级用户创建，并且默认对所有 DDL 生效。
- 没有 `ON SCHEMA` 过滤，函数里自行判断 `object_identity` 前缀。
- `AFTER LOGON` / `AFTER SERVERERROR` 无对应；登录钩子用连接池初始化或 `ALTER ROLE ... SET`。

## 6. 禁用、删除与依赖

```sql
ALTER TABLE t_order DISABLE TRIGGER trg_order_bi;   -- 表所有者可做
ALTER TABLE t_order ENABLE TRIGGER trg_order_bi;
DROP TRIGGER IF EXISTS trg_order_bi ON t_order;
```

- `DISABLE TRIGGER ALL` 会涉及内部触发器，通常需要超级用户；不要在生产随手使用。
- 触发器依赖函数：删除函数前先删触发器（或 `DROP FUNCTION ... CASCADE`，会连带删触发器）。
- 触发器函数名建议 `trg_<表>_<事件>`，与触发器同名或加后缀，便于排查。
- `pg_trigger` / `pg_proc` 可查现状：

```sql
SELECT tgname, pg_get_triggerdef(oid)
FROM pg_trigger WHERE tgrelid = 't_order'::regclass AND NOT tgisinternal;
```

## 7. 风险与差异

| 风险 | 说明 |
|---|---|
| 自治事务 | 触发器里不能 `COMMIT`；Oracle 的 `PRAGMA AUTONOMOUS_TRANSACTION` 写日志方案要改成队列表。 |
| 触发器顺序 | PG 按名字母序；Oracle 可用 `FOLLOWS`。多触发器有依赖时重命名排序。 |
| 递归触发 | PG 默认允许递归触发（受 `max_stack_depth` 限制）；Oracle 有 `RECURSIVE` 限制，注意死循环。 |
| 性能 | 行级触发器逐行执行；批量导入时考虑先禁用触发器，导入后统一校验（注意数据一致性）。 |
| 迁移数据 | `COPY` 也会触发 `BEFORE/AFTER` 行触发器（除非用 `ALTER TABLE ... DISABLE TRIGGER`）。 |
| 安全 | `SECURITY DEFINER` 触发器函数要固定 `search_path`。 |

## 8. 自检

- [ ] 触发器函数返回类型是 `trigger`，函数体有正确的 `RETURN NEW/OLD/NULL`。
- [ ] `:NEW`/`:OLD` 已全部改掉，`INSERTING/UPDATING/DELETING` 已改成 `TG_OP`。
- [ ] `WHEN` 条件没有子查询；列级条件放在函数体或 `UPDATE OF`。
- [ ] 触发器名字母序符合业务顺序要求。
- [ ] 行级/语句级选择正确；需要读同表数据时用过渡表。
- [ ] 禁用/启用语句、依赖删除顺序已写入部署脚本。
