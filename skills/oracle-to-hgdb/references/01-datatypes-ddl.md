# 01 数据类型与 DDL

## 1. 类型映射

| Oracle | HGDB / PG14 | 说明 |
|---|---|---|
| `VARCHAR2(n)` / `VARCHAR(n)` | `varchar(n)` | PG 的 n 按字符计；Oracle 默认 `BYTE`。多字节场景要确认，必要时用 `varchar` + `CHECK (octet_length(c) <= n)`。 |
| `VARCHAR2(n CHAR)` | `varchar(n)` | 语义一致（按字符）。 |
| `NVARCHAR2(n)` / `NCHAR(n)` | `varchar(n)` / `char(n)` | 库编码为 UTF-8 时等价。 |
| `CHAR(n)` | `char(n)` | 都按空格补齐；但 PG `length()` 会去掉尾空格，Oracle 返回 n，见 §2。 |
| `NUMBER(p,s)` | `numeric(p,s)` | 金额/比率保持精度；Oracle 允许负 scale（按十位/百位取整），PG14 的 `numeric(p,s)` 要求 `0 ≤ s ≤ p`，负 scale 场景改用 `numeric` + `round()` 处理。 |
| `NUMBER(p)` | `numeric(p)` | 等价于 `numeric(p,0)`。 |
| `NUMBER` | `numeric` | 任意精度；不要图省事改成 `bigint`（`NUMBER` 可达 38 位）。 |
| `INTEGER` / `INT` | `numeric(38)` 或 `bigint` | Oracle `INTEGER` = `NUMBER(38)`；业务值域可控时用 `bigint` 并写进报告。 |
| `FLOAT(b)` | `real`（b≤24）/ `double precision` | Oracle 的 b 是二进制精度。 |
| `BINARY_FLOAT` / `BINARY_DOUBLE` | `real` / `double precision` | 浮点误差语义接近。 |
| `DATE` | `timestamp(0)` | **不要**映射成 `date`：Oracle DATE 含时分秒。 |
| `TIMESTAMP(p)` | `timestamp(p)` | PG 最多 6 位小数；Oracle 可到 9 位，超出会丢精度。 |
| `TIMESTAMP WITH TIME ZONE` | `timestamptz(p)` | 会话时区显示语义接近。 |
| `TIMESTAMP WITH LOCAL TIME ZONE` | `timestamptz(p)` | Oracle 按会话时区存储/显示；PG 存 UTC、按 `TimeZone` 显示，需验证比较与输出。 |
| `INTERVAL YEAR TO MONTH` | `interval year to month` | |
| `INTERVAL DAY TO SECOND` | `interval day to second` | |
| `CLOB` / `NCLOB` | `text` | PG `text` 上限约 1GB；Oracle CLOB 上限更大，超大文本要评估。 |
| `BLOB` | `bytea` | 上限约 1GB；大对象考虑 `lo` 类型。 |
| `RAW(n)` | `bytea` | |
| `LONG` / `LONG RAW` | `text` / `bytea` | 已废弃类型，先确认数据量。 |
| `ROWID` / `UROWID` | `text`（存主键）或业务键 | PG `ctid` 会随 VACUUM/UPDATE 变化，不能当稳定行标识。 |
| `XMLTYPE` | `xml` | 查询函数不同，见 08。 |
| `SDO_GEOMETRY` | `geometry`（PostGIS） | 需要扩展；无扩展时降级为 `text` 并标注。 |
| `BOOLEAN`（PL/SQL） | `boolean` | |
| `PLS_INTEGER` / `BINARY_INTEGER` / `SIMPLE_INTEGER` | `integer` / `bigint` | |
| `NATURAL` / `POSITIVE` / `SIGNTYPE` | `integer` + `CHECK` | 约束语义要保留。 |
| `%TYPE` / `%ROWTYPE` | 同名语法 | PL/pgSQL 支持。 |
| `SYS_REFCURSOR` | `refcursor` | |
| `RECORD` / `TABLE OF` / `VARRAY` | 复合类型 / 数组 / 临时表 | 见 03、05。 |
| `BFILE` | 无 | 存路径或对象存储，不能直接迁移。 |
| `ANYDATA` / `ANYTYPE` | `jsonb` 或 `text` | 无强类型等价物。 |
| `JSON`（21c） | `jsonb` | 建议 `jsonb`，查询走 `->`/`@>`/`jsonb_path_query`。 |

## 2. 必须显式处理的类型语义

### 空串等于 NULL
Oracle 中 `''` 就是 NULL；PG 中 `''` 是合法空串。影响：
- `col = ''` 在 Oracle 永假，在 PG 可能为真。
- `NVL(col, '')` 在 Oracle 返回 NULL，在 PG 返回 `''`。
- `NOT NULL` 列在 PG 仍可插入 `''`。
- `CHECK (col <> '')` 在 Oracle 恒不成立（因为 NULL），在 PG 会拦住空串。

处理建议：对「空串应视为未填」的列，加 `CHECK (col <> '')`（保留 `NOT NULL` 时），并在报告标注应用层写入路径。

### CHAR 的补齐与长度
- 存储：都补齐到 n。
- 比较：Oracle 补齐比较；PG `bpchar` 比较忽略尾空格，行为接近。
- 长度：`length(char_col)` 在 PG 会去掉尾空格（返回实际字符数），Oracle 返回 n。用 `octet_length` 或 `char_length(btrim(...))` 前先确认业务含义。

### 日期时间
- `DATE` → `timestamp(0)`；应用读取时格式可能变化（`2024-01-01 00:00:00`）。
- Oracle `SYSDATE` 是数据库服务器时间、秒精度；PG `now()` 是事务开始时间（`transaction_timestamp()`），`clock_timestamp()` 才是当前时刻。**长事务里两者不同**。
- `CURRENT_DATE`、`CURRENT_TIMESTAMP` 也是事务开始时间；需要实时时间用 `clock_timestamp()`。

### NUMBER 与隐式转换
- Oracle `'123' = 123` 自动转换；PG `text = numeric` 直接报错。所有比较/赋值点显式 `::numeric` / `::text`。
- Oracle `NUMBER` 的 `ROUND`/`TRUNC` 与 PG `numeric` 行为一致（四舍五入 away from zero），但浮点列（`binary_double`）行为不同。

### 大对象
- `text`/`bytea` 单值上限约 1GB；超过时用 `lo` 大对象或外部存储。
- Oracle `DBMS_LOB` 操作要改写成内置字符串/字节函数（见 08）。

## 3. 建表语句清理

删除以下子句（PG 不支持或由存储层管理）：

```
PCTFREE / PCTUSED / INITRANS / MAXTRANS
STORAGE (...) / TABLESPACE ... / SEGMENT CREATION ...
LOGGING / NOLOGGING / COMPRESS / NOCOMPRESS
CACHE / NOCACHE（表级）
PARALLEL / NOPARALLEL / MONITORING
ENABLE ROW MOVEMENT
ORGANIZATION INDEX / ORGANIZATION HEAP
USING INDEX ...（约束上的索引子句）
```

保留并改写的：

| Oracle | PG14 |
|---|---|
| `DEFAULT SYSDATE` | `DEFAULT LOCALTIMESTAMP(0)` |
| `DEFAULT SYSTIMESTAMP` | `DEFAULT CURRENT_TIMESTAMP` |
| `DEFAULT SYS_GUID()` | `DEFAULT gen_random_uuid()`（需 `pgcrypto`） |
| `GENERATED ALWAYS AS IDENTITY` | 同语法 |
| `GENERATED BY DEFAULT ON NULL AS IDENTITY` | PG14 不支持 `ON NULL`，改 `GENERATED BY DEFAULT` + 应用层/触发器补默认 |
| `ENABLE` / `DISABLE`（约束） | 默认启用；`NOVALIDATE` → `NOT VALID` |
| `ON COMMIT DELETE ROWS`（全局临时表） | `ON COMMIT DELETE ROWS`（`CREATE TEMP TABLE`） |
| `CREATE GLOBAL TEMPORARY TABLE` | `CREATE TEMP TABLE` |

`ALTER TABLE` 映射：

| Oracle | PG14 |
|---|---|
| `ADD (c type, ...)` | `ADD COLUMN c type, ...` |
| `MODIFY (c type)` | `ALTER COLUMN c TYPE type` |
| `MODIFY (c DEFAULT x)` | `ALTER COLUMN c SET DEFAULT x` |
| `MODIFY (c NOT NULL)` | `ALTER COLUMN c SET NOT NULL` |
| `DROP COLUMN c` | `DROP COLUMN c` |
| `RENAME COLUMN a TO b` | `RENAME COLUMN a TO b` |
| `SET UNUSED (c)` | 直接 `DROP COLUMN c`（PG 无 unused） |
| `MOVE TABLESPACE` | `VACUUM FULL` / `CLUSTER`（重写表） |
| `SHRINK SPACE` | `VACUUM FULL` |
| `TRUNCATE ... DROP STORAGE` | `TRUNCATE` |

## 4. 约束

- 主键/唯一/外键/`CHECK` 语法基本一致；去掉 `USING INDEX`、`ENABLE`、存储子句。
- `ON DELETE CASCADE` / `SET NULL` 一致。
- `DEFERRABLE INITIALLY DEFERRED` 一致（外键、唯一约束）。
- 外键目标列必须有唯一约束/主键。
- `NOVALIDATE` → `NOT VALID`；之后可 `VALIDATE CONSTRAINT`。
- 约束名：Oracle `SYS_C...` 建议改成有意义的 `pk_/fk_/ck_/uk_` 命名，避免与 PG 自动命名冲突。

## 5. 索引

- 删除 `TABLESPACE`、`COMPUTE STATISTICS`、`NOLOGGING`、`PARALLEL`。
- 位图索引 → 无直接等价物：等值/低基数列用 btree，数组/JSON 用 GIN，范围用 BRIN；在报告中说明。
- 函数索引 → 表达式索引，函数必须 `IMMUTABLE`。
- 反向键索引 → 无。
- 不可见索引 → 无（PG14）；不要建无用索引。
- 分区表上的 `LOCAL` 索引 → `CREATE INDEX ON 分区表 (...)` 自动成为分区索引；唯一索引必须包含分区键。
- 大表建索引用 `CREATE INDEX CONCURRENTLY`（不能在事务块内）。

## 6. 序列

```sql
-- Oracle
CREATE SEQUENCE seq_order_id START WITH 1000 INCREMENT BY 1 MAXVALUE 9999999999 NOCACHE NOCYCLE ORDER;
```

```sql
-- PG14（ORDER 无对应，去掉并在报告说明）
CREATE SEQUENCE seq_order_id START WITH 1000 INCREMENT BY 1 MAXVALUE 9999999999 CACHE 1 NO CYCLE;
```

| Oracle | PG14 |
|---|---|
| `seq.NEXTVAL` | `nextval('seq')` |
| `seq.CURRVAL` | `currval('seq')`（本会话未取过会报错，同 Oracle） |
| 列默认值 `DEFAULT seq.NEXTVAL` | `DEFAULT nextval('seq')` 或 `GENERATED ... AS IDENTITY` |
| `ALTER SEQUENCE ... RESTART START WITH n` | `ALTER SEQUENCE ... RESTART WITH n` |
| `CACHE n` / `NOCACHE` | `CACHE n` / `CACHE 1` |
| `ORDER` / `NOORDER` | 无（忽略） |

注意：PG 序列和 Oracle 一样不参与事务回滚，回滚会产生空洞；迁移时要设定 `START WITH` 避免与存量主键冲突（先 `SELECT max(id)`）。

## 7. 同义词

PG 没有同义词。按优先级：

1. **改调用点**：应用 SQL、视图、函数体里统一改成 `schema.object`。
2. **`search_path`**：`ALTER ROLE app SET search_path = app, public;`（对 schema 级同义词有效；对单对象同义词不够）。
3. **视图兜底**：`CREATE VIEW syn_name AS SELECT * FROM schema.tab;`——只读；需要 DML 时用可更新视图或 `INSTEAD OF` 触发器（成本高，不推荐）。
4. **`PUBLIC SYNONYM`**：优先把对象放 `public` 或统一 `search_path`，不要为每个同义词建视图。

## 8. 临时表

```sql
-- Oracle
CREATE GLOBAL TEMPORARY TABLE gtt_tmp (id NUMBER, v VARCHAR2(100)) ON COMMIT DELETE ROWS;
```
```sql
CREATE TEMP TABLE gtt_tmp (id numeric, v varchar(100)) ON COMMIT DELETE ROWS;
```
- `ON COMMIT PRESERVE ROWS` 是 PG 默认，可省略。
- Oracle 全局临时表定义全局共享、数据会话隔离；PG 临时表定义也随会话创建（每会话一份），语义可接受。
- 临时表上不要依赖固定 OID/统计信息；大批量写入后 `ANALYZE`。

## 9. 分区

| Oracle | PG14 |
|---|---|
| `PARTITION BY RANGE (c)` + `VALUES LESS THAN (...)` | `PARTITION BY RANGE (c)`，子表 `FOR VALUES FROM (a) TO (b)` |
| `MAXVALUE` | `MAXVALUE`（最后一个分区）或 `DEFAULT` 分区 |
| `PARTITION BY LIST (c)` + `VALUES (...)` | `FOR VALUES IN (...)` |
| `PARTITION BY HASH (c) PARTITIONS 4` | `PARTITION BY HASH (c)` + 4 个 `FOR VALUES WITH (MODULUS 4, REMAINDER n)` |
| `INTERVAL (...)` 自动分区 | 无内置；用 `pg_partman` 或定时任务 |
| 复合分区（range-list 等） | PG 支持多级分区：子分区表本身再 `PARTITION BY`，但没有 Oracle 的模板语法 |
| `EXCHANGE PARTITION` | `DETACH PARTITION` + `ATTACH PARTITION`（14 支持 `DETACH ... CONCURRENTLY`） |
| `ADD PARTITION` | `CREATE TABLE ... PARTITION OF ...` |
| 全局索引 | 无；分区表索引默认分区索引 |

注意：分区表主键/唯一约束必须包含分区键；`ATTACH PARTITION` 会加锁并校验数据。

## 10. 注释、权限、角色

```sql
COMMENT ON TABLE t IS '...';
COMMENT ON COLUMN t.c IS '...';
GRANT SELECT, INSERT ON t TO app_role;
GRANT EXECUTE ON FUNCTION f(numeric) TO app_role;
```

- `CREATE USER u IDENTIFIED BY p` → `CREATE ROLE u LOGIN PASSWORD 'p'`。
- `ALTER USER u IDENTIFIED BY p` → `ALTER ROLE u PASSWORD 'p'`。
- `GRANT ... WITH GRANT OPTION` 一致。
- `GRANT EXECUTE ON pkg.proc` → 函数需带参数类型：`GRANT EXECUTE ON FUNCTION pkg.proc(numeric) TO ...`；批量用 `GRANT EXECUTE ON ALL FUNCTIONS IN SCHEMA pkg TO ...`。
- `DEFAULT TABLESPACE`、`PROFILE`、`QUOTA` 无对应，删除并在报告说明。

## 11. 其他 DDL

| Oracle | 处理 |
|---|---|
| `CREATE DATABASE LINK` | `dblink` / `postgres_fdw` / `oracle_fdw`；改写跨库 SQL。 |
| `CREATE DIRECTORY` | 无；外部文件用 `COPY`、`pg_read_file`（超级用户）或应用侧。 |
| `DBMS_SCHEDULER` / `DBMS_JOB` | `pg_cron` 或外部调度。 |
| `AUDIT ...` | `pgaudit` 扩展或触发器审计。 |
| `FLASHBACK` / `AS OF` | 无；用备份、归档表或时间戳列自行实现。 |
| `CREATE TYPE ... AS OBJECT` | 复合类型；`MEMBER FUNCTION` 改为接收该类型参数的函数。 |
| `CREATE TYPE ... AS TABLE OF` | 数组类型或临时表；`TABLE()` 调用改为 `unnest`。 |
| `CREATE OR REPLACE SYNONYM` | 见 §7。 |
| `RENAME a TO b` | `ALTER TABLE a RENAME TO b;` |
| `CREATE TABLE ... AS SELECT` | 同语法；可加 `WITH NO DATA`。 |

## 12. 示例

```sql
-- Oracle
CREATE TABLE t_order (
  id            NUMBER(18)      NOT NULL,
  order_no      VARCHAR2(32 BYTE) NOT NULL,
  amount        NUMBER(12,2)    DEFAULT 0 NOT NULL,
  status        CHAR(1)         DEFAULT 'N' NOT NULL,
  created_at    DATE            DEFAULT SYSDATE NOT NULL,
  remark        VARCHAR2(500),
  CONSTRAINT pk_t_order PRIMARY KEY (id) USING INDEX TABLESPACE users,
  CONSTRAINT ck_t_order_amount CHECK (amount >= 0)
) TABLESPACE users PCTFREE 10;
```

```sql
-- HGDB / PG14
CREATE TABLE t_order (
  id            numeric(18)   NOT NULL,
  order_no      varchar(32)   NOT NULL,
  amount        numeric(12,2) DEFAULT 0 NOT NULL,
  status        char(1)       DEFAULT 'N' NOT NULL,
  created_at    timestamp(0)  DEFAULT LOCALTIMESTAMP(0) NOT NULL,
  remark        varchar(500),
  CONSTRAINT pk_t_order PRIMARY KEY (id),
  CONSTRAINT ck_t_order_amount CHECK (amount >= 0)
);
```
