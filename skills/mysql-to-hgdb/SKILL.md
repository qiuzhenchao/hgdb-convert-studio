# MySQL → HGDB V9 转换

HGDB V9 内核是 PostgreSQL 14。MySQL 源**不走 Oracle 兼容模式**，但目标形态决定改写力度：目标是 **HGDB-V9-MySQL（MySQL 兼容 / plmysql）** 时走**最小改写**——实测支持的 MySQL 写法原样保留，只改不支持项；目标是 **HGDB-V9-PostgreSQL / Oracle** 时按 HGDB V9 标准写法完整改写（见下方“完整改写”清单）。数据库对象读取由工作台的 `ReadMysqlObjects` 完成（`SHOW CREATE ...`，表按外键依赖排序），转换时以真实 DDL 为准，不要凭印象补字段。

## 工作流程

1. **确认目标**：目标 schema、是否保留原表名（MySQL 小写、无 schema 前缀）、是否需要数据迁移。
2. **按依赖排序**：被引用表 → 引用表（工作台读取时已排序）→ 视图 → 函数/过程 → 触发器/事件。
3. **逐对象改写**：一次一个对象；表结构、索引、注释、外键放在同一份脚本里。
4. **自检**：反引号清零、类型可编译、自增列唯一、索引名在 schema 内不重复、外键引用的表和列存在。

| MySQL | HGDB V9 | 说明 |
|---|---|---|

| `TINYINT` | `SMALLINT` | |
| `SMALLINT` / `MEDIUMINT` | `SMALLINT` / `INTEGER` | |
| `INT` / `INTEGER` | `INTEGER` | |
| `BIGINT` | `BIGINT` | |

| `BIGINT UNSIGNED` | `BIGINT` 或 `NUMERIC(20)` | `BIGINT` 会缩小上限，必须标注 |
| `DECIMAL(p,s)` | `NUMERIC(p,s)` | |
| `FLOAT` / `DOUBLE` | `REAL` / `DOUBLE PRECISION` | |
| `DATETIME` / `TIMESTAMP` | `TIMESTAMP` | 不带时区 |
| `DATE` / `TIME` / `YEAR` | `DATE` / `TIME` / `INTEGER` | |

| `BINARY` / `VARBINARY` / `*BLOB` | `BYTEA` | |

## 建表（DDL）

```sql
CREATE TABLE `orders` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT,
  `order_no` varchar(32) COLLATE utf8mb4_unicode_ci NOT NULL,
  `status` tinyint NOT NULL DEFAULT '0' COMMENT '0待付款 1已付款',
  `amount` decimal(12,2) NOT NULL DEFAULT '0.00',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_orders_no` (`order_no`),
  KEY `idx_orders_status` (`status`,`created_at`),
  CONSTRAINT `fk_orders_user` FOREIGN KEY (`user_id`) REFERENCES `users` (`id`)
) ENGINE=InnoDB AUTO_INCREMENT=6 DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='订单表'
```

改写要点：

- 标识符：`` `name` `` → 小写无引号 `name`；保留字或必须区分大小写才用双引号，全链路一致。
- 表选项：删除 `ENGINE`、`DEFAULT CHARSET`、`COLLATE`、`AUTO_INCREMENT=`、`ROW_FORMAT`；`PARTITION BY` 需在 HGDB 上重建并标注。
- 自增：`AUTO_INCREMENT` → `GENERATED BY DEFAULT AS IDENTITY`（只能单列、整数类型；不要再用 `serial`，除非用户明确要求）。
- 注释：表/列 `COMMENT '...'` → `COMMENT ON TABLE / COLUMN ... IS '...'`。
## 先判断目标形态（决定改写力度）

| 目标 | 改写策略 | 例程 |
| --- | --- | --- |
| HGDB-V9-MySQL（MySQL 协议端口，内置 plmysql） | **最小改写**：实测支持的写法原样保留 | `LANGUAGE plmysql`，过程体保持 MySQL 写法 |
| HGDB-V9-PostgreSQL / HGDB-V9-Oracle（PG 协议端口） | **完整改写**：按下面“完整改写”清单逐项转换 | 改写为 PL/pgSQL / 触发器函数 |

最小改写（MySQL 兼容目标）只处理这些实测不支持项：

- `SET('a','b')` 类型 → `VARCHAR(255)`；
- 空间类型（GEOMETRY/POINT/…）→ `BYTEA`，`SPATIAL KEY` → 删除；
- `PARTITION BY ...` → 删除分区子句；
- 视图 `ALGORITHM=` / `DEFINER=` / `SQL SECURITY` → 删除；
- `utf8mb4_0900_*` 排序规则 → `utf8mb4_unicode_ci`；
- `JSON_EXTRACT(j,'$.a')` → `j ->> 'a'`（多级用 `#>>`）；
- `FOUND_ROWS()` → 用 `COUNT(*)` 改写；
- `EVENT` → pgAgent / pg_cron；
- `DROP TRIGGER` → `DROP FUNCTION IF EXISTS <触发器名>_fn() CASCADE`；
- 例程体内：`SIGNAL` → `RAISE EXCEPTION`、`DECLARE ... HANDLER` → `EXIT WHEN NOT FOUND`、`WHILE ... DO` → `LOOP`、`label:` → `<<label>>`、`LAST_INSERT_ID()` → `LASTVAL()`。

## 完整改写（PostgreSQL / Oracle 形态目标）

- 索引：`UNIQUE KEY` → `CONSTRAINT <name> UNIQUE (...)`；普通 `KEY/INDEX` → 建表之后单独 `CREATE INDEX`；`FULLTEXT/SPATIAL` 需替换（PostgreSQL 全文检索 / PostGIS）或标注；前缀索引 `col(10)` 去掉前缀长度。
- 外键：保留 `CONSTRAINT ... FOREIGN KEY ... REFERENCES ... [ON DELETE/UPDATE ...]`；被引用表必须先建。
- 默认值：`DEFAULT CURRENT_TIMESTAMP` 保留；`ON UPDATE CURRENT_TIMESTAMP` 必须补 `BEFORE UPDATE` 触发器（函数 + `CREATE TRIGGER`）；`'0000-00-00'` 改为 `NULL` 或合法时间；数值默认值去掉引号。
- 字符集/排序规则：MySQL 的 `utf8mb4_unicode_ci` 与 HGDB 的 `COLLATE` 不等价，迁移后按业务确认大小写与重音比较行为。

## 视图

```sql
CREATE ALGORITHM=UNDEFINED DEFINER=`root`@`%` SQL SECURITY DEFINER VIEW `v_x` AS ...
```

→ 去掉 `ALGORITHM` / `DEFINER` / `SQL SECURITY`，改为：

```sql
CREATE OR REPLACE VIEW v_x AS
SELECT ...;
```

视图内 MySQL 方言（`IFNULL`、`NOW()`、反引号）按下面的查询规则改写。

## 存储过程、函数、触发器、事件

MySQL 与 PL/pgSQL 的控制流、异常、动态 SQL都不同，必须逐段改写：

| MySQL | HGDB V9 / PL/pgSQL |
|---|---|
| `CREATE PROCEDURE p(IN a INT, OUT b INT)` | `CREATE PROCEDURE p(a INTEGER, INOUT/OUT b INTEGER)` |
| `DELIMITER` | 不需要；函数体用 `$$` 包裹 |
| `DECLARE x INT DEFAULT 0;` | `DECLARE x INTEGER := 0;`（放在 `BEGIN` 之后） |
| `IF ... THEN ... ELSE ... END IF;` | `IF ... THEN ... ELSE ... END IF;`（可保留） |
| `WHILE ... DO ... END WHILE;` | `WHILE ... LOOP ... END LOOP;` |
| `SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT='...';` | `RAISE EXCEPTION '...';` |
| `SELECT ... INTO var` | `SELECT ... INTO var;`（注意无行时报错语义） |
| 游标 / `HANDLER` | 显式 `DECLARE cur CURSOR ...` + `EXIT WHEN NOT FOUND` |
| `CREATE TRIGGER ... FOR EACH ROW BEGIN ... END` | `CREATE FUNCTION ... RETURNS trigger` + `CREATE TRIGGER ... EXECUTE FUNCTION ...`；`NEW/OLD` 可直接用 |
| `CREATE EVENT ... ON SCHEDULE ... DO ...` | 无直接等价物，改写为 pg_cron / pgAgent 并标注 |

触发器示例（`ON UPDATE CURRENT_TIMESTAMP` 的等价实现）：

```sql
CREATE OR REPLACE FUNCTION trg_orders_updated_at() RETURNS trigger AS $$
BEGIN
  NEW.updated_at := CURRENT_TIMESTAMP;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_orders_updated_at
BEFORE UPDATE ON orders
FOR EACH ROW EXECUTE FUNCTION trg_orders_updated_at();
```

## 查询与 DML 方言

| MySQL | HGDB V9 |
|---|---|
| `IFNULL(a,b)` | `COALESCE(a,b)` |
| `NOW()` / `CURDATE()` / `CURTIME()` | `CURRENT_TIMESTAMP` / `CURRENT_DATE` / `CURRENT_TIME` |
| `LIMIT 10, 20` | `LIMIT 20 OFFSET 10` |
| `GROUP_CONCAT(x SEPARATOR ',')` | `STRING_AGG(x, ',')`（注意 `DISTINCT` / `ORDER BY`） |
| `DATE_FORMAT(d, '%Y-%m-%d')` | `TO_CHAR(d, 'YYYY-MM-DD')` |
| `STR_TO_DATE(s, '%Y-%m-%d')` | `TO_DATE(s, 'YYYY-MM-DD')` / `TO_TIMESTAMP` |
| `ON DUPLICATE KEY UPDATE` | `INSERT ... ON CONFLICT (...) DO UPDATE SET ...` |
| `INSERT IGNORE` | `INSERT ... ON CONFLICT DO NOTHING` |
| `REPLACE INTO` | `INSERT ... ON CONFLICT (...) DO UPDATE`（或先 DELETE） |
| `REGEXP` | `~` / `~*` |
| `DIV` | `/` + `div()` / `floor()` |
| `b'1'` / `x'0A'` | `true` / `'\x0A'::bytea` |
| `@var` 用户变量 | CTE / 参数 / 临时表 |
| 反斜杠转义 `'a\'b'` | 标准字符串 `'a''b'`（`standard_conforming_strings=on`） |

## 验证清单

- 反引号已全部消失；没有残留 `ENGINE=`、`COLLATE`、`AUTO_INCREMENT`、`UNSIGNED`。
- 每个 `AUTO_INCREMENT` 列都有 identity，且是主键或唯一键的第一列。
- 外键引用的表与列存在，表顺序满足依赖。
- 索引名在 schema 内唯一（MySQL 索引名是按表唯一的）。
- 时间默认值与 `ON UPDATE` 语义有触发器或明确标注。
- 过程/函数/触发器已换成 PL/pgSQL 结构，`RAISE`、`LOOP`、`DECLARE` 配对完整。
